# ybook

`ybook` превращает публичный YouTube-канал в персональную EPUB-книгу: получает канал, плейлисты, загрузки и метаданные видео через **YouTube Data API v3**, скачивает готовые субтитры через **youtube-transcript-api** и **yt-dlp**, а затем собирает один **EPUB 3** с вложенным оглавлением. По умолчанию расшифровки очищаются через любой **OpenAI-совместимый** endpoint и получают аннотацию из 2–4 предложений; LLM можно отключить и собрать книгу из нормализованных расшифровок без изменений (`--no-llm`). Аудио не скачивается, распознавание речи не выполняется: если субтитров на нужном языке нет, видео пропускается.

> **Статус:** `0.1.0`, бета. Это инструмент для **личного использования**, а не сервис и не продакшен-решение. Нужен Python **3.11+**. Поддерживается только **EPUB**; обложка не создаётся. Язык расшифровок по умолчанию — **английский** (`en`), его можно изменить в конфигурации или флагом `--language`.

## Что делает ybook

Один запуск `ybook all` выполняет четыре стадии:

1. **`fetch`** — разрешает канал, получает публичные плейлисты, плейлист загрузок и метаданные видео через YouTube Data API v3; сохраняет всё в SQLite и пишет отладочные снимки API.
2. **`transcripts`** — скачивает готовые субтитры через `youtube-transcript-api`, при неудаче — через `yt-dlp`; сохраняет сырой ответ и нормализованный текст.
3. **`clean`** — по умолчанию очищает текст через LLM по чанкам, проверяет качество и генерирует аннотацию главы; с `--no-llm` (или `llm.enabled = false`) просто копирует нормализованную расшифровку без изменений и без аннотаций.
4. **`build`** — собирает EPUB 3 из SQLite и очищенных файлов, полностью офлайн.

Что поддерживается:

- **YouTube Data API v3**: канал, публичные плейлисты, загрузки, метаданные видео, пагинация;
- **расшифровки**: `youtube-transcript-api` как основной источник и `yt-dlp` как запасной;
- **очистка текста** через OpenAI-совместимый `POST {base_url}/chat/completions` — по умолчанию; режим `--no-llm` копирует нормализованные расшифровки без изменений и не требует ключа LLM;
- **аннотации** из 2–4 предложений для каждой главы — только при включённом LLM;
- **EPUB 3** с вложенным оглавлением, NCX для старых читалок, титульной страницей и страницей «About this book»;
- **SQLite-состояние**, идемпотентные перезапуски, `--force`, `--limit`;
- **офлайн-сборка** книги из уже очищенных глав.

## Чего ybook не делает

| Ограничение | Как это проявляется |
|---|---|
| **Не скачивает аудио и не запускает Whisper/ASR** | Нет готовых субтитров — видео получает `skipped`. Это осознанное решение: меньше зависимостей, меньше нарушений, быстрее работа. |
| **Не переводит** | Очистка сохраняет язык оригинала. Если субтитров на выбранном языке нет, видео пропускается, а не переводится и не транскрибируется. |
| **Не принимает машинный перевод авто-субтитров** | Для авто-дорожек `yt-dlp` принимаются только оригинальные файлы с суффиксом `-orig` (`en-orig`, `ru-orig` и т.п.). Переведённая дорожка `en.vtt` для неанглийского видео отклоняется. |
| **Не делает обложку** | EPUB собирается без изображения обложки — по требованию проекта. |
| **Не делает PDF, FB2, MOBI** | Единственный формат вывода — EPUB. |
| **Не гарантирует наличие субтитров** | Официальный YouTube API не отдаёт сторонние субтитры. `youtube-transcript-api` и `yt-dlp` — неофициальные инструменты и могут ломаться при изменениях YouTube. |
| **Не обходит приватность, возрастные ограничения, DRM и платный доступ** | Приватные, удалённые и недоступные видео пропускаются. |
| **Не редактирует текст в режиме без LLM** | `--no-llm` копирует нормализованную расшифровку как есть: не добавляет пунктуацию, заглавные буквы и абзацы, не запускает quality guard и не создаёт аннотации. Это неотредактированный текст расшифровки (обычно ASR). |
| **Не гарантирует качество LLM** | При включённом LLM очистка и аннотации могут содержать ошибки. Проверяйте важные факты. |

## Требования и установка

Нужен **Python 3.11+**. `yt-dlp` устанавливается как обычная Python-зависимость. Отдельный бинарник `ffmpeg` для этого сценария не нужен: аудио не скачивается, `yt-dlp` вызывается с `--skip-download`. Держите `yt-dlp` актуальным (`pip install -U yt-dlp` или `uv sync --upgrade`): YouTube часто меняет защиту, и старые версии могут перестать получать субтитры.

### Вариант 1: uv

```bash
git clone <repo-url> ybook
cd ybook
uv sync
uv run ybook --help
```

Для разработки:

```bash
uv sync --extra dev
uv run pytest -q
uv run ruff check src tests
```

### Вариант 2: pip

```bash
cd ybook
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e .
ybook --help
ybook --version
```

Для разработки:

```bash
pip install -e ".[dev]"
pytest -q
```

Проверка установки:

```bash
ybook --version     # ybook 0.1.0
ybook --help
```

Проект также запускается как модуль:

```bash
python -m ybook --help
python -m ybook status
```

Для проверки EPUB можно отдельно установить `epubcheck` (Java-утилита, в зависимости проекта не входит):

```bash
epubcheck out/book.epub
```

## Быстрый старт

### 1. Получите ключ YouTube Data API v3

1. Откройте [Google Cloud Console](https://console.cloud.google.com/).
2. Создайте проект или выберите существующий.
3. Включите **YouTube Data API v3**: *APIs & Services → Library → YouTube Data API v3 → Enable*.
4. Создайте API key: *APIs & Services → Credentials → Create credentials → API key*.
5. Ограничьте ключ: разрешите только YouTube Data API v3 и, если удобно, ваш IP.

Дневная квота по умолчанию — **10 000 единиц**. Обычные list-запросы стоят около 1 единицы; резервный `search.list` для `/c/...` — 100 единиц. Подробная таблица — в разделе [«YouTube: канал и метаданные»](#youtube-канал-и-метаданные).

### 2. Настройте `.env`

Подойдёт любой endpoint, реализующий `POST {base_url}/chat/completions` в формате OpenAI Chat Completions. SDK OpenAI не используется — только `httpx`, поэтому провайдер меняется без изменения кода.

```bash
cp .env.example .env
```

Минимум для режима с LLM (по умолчанию):

```dotenv
YOUTUBE_API_KEY=ваш-ключ-youtube
OPENAI_API_KEY=ваш-ключ-llm
```

`OPENAI_API_KEY` нужен только при `llm.enabled = true` (значение по умолчанию). Если LLM выключен (`llm.enabled = false` или флаг `--no-llm`), достаточно `YOUTUBE_API_KEY`: `ybook clean --no-llm` скопирует уже скачанные расшифровки, а `ybook all --no-llm` пройдёт `fetch → transcripts → clean (копия) → build` без ключа LLM.

Если провайдер не OpenAI, задайте базовый URL и модель в `ybook.toml` или через переменные окружения `OPENAI_BASE_URL` и `YBOOK_LLM_MODEL`. Примеры — в разделе [«Примеры LLM-провайдеров»](#примеры-llm-провайдеров).

### 3. Настройте `ybook.toml`

```bash
cp ybook.example.toml ybook.toml
```

Минимум, который нужно изменить:

```toml
channel = "https://www.youtube.com/@example"

[paths]
data_dir = "data"
output_dir = "out"

[youtube]
api_key_env = "YOUTUBE_API_KEY"

[llm]
base_url = "https://api.openai.com/v1"
api_key_env = "OPENAI_API_KEY"
model = "gpt-4.1-mini"
```

Остальные значения по умолчанию описаны в разделе [«Конфигурация»](#конфигурация). Полный шаблон — в `ybook.example.toml`.

### 4. Первый запуск: ограничьте выборку

```bash
ybook all --limit 3
```

`--limit 3` ограничивает **число обрабатываемых видео на стадиях `transcripts` и `clean`**, а не число глав в книге: часть видео может не иметь субтитров и получить `skipped`. Метаданные канала при этом загружаются полностью. Это удобный способ проверить ключи, субтитры и качество LLM на небольшой выборке.

Без LLM используйте `ybook all --limit 3 --no-llm`: понадобится только ключ YouTube, а главы будут собраны из нормализованных расшифровок без редактирования.

### 5. Полный запуск

```bash
ybook all
```

Или с явной ссылкой и путём:

```bash
ybook all --channel "https://www.youtube.com/@example" --out out/my-book.epub --language en
```

Порядок стадий: `fetch → transcripts → clean → build`. Если стадия завершилась исключением, последующие не запускаются. Отдельные видео со статусами `skipped`/`failed` конвейер не прерывают — стадия завершается, а итог виден в сводке.

### 6. Где появится EPUB

По умолчанию:

```text
out/book.epub
```

Путь по умолчанию — `config.paths.output_dir / "book.epub"`. Флаг `--out` задаёт другой путь; относительный путь считается от **текущего рабочего каталога**, а не от каталога конфига. Каталог назначения создаётся автоматически.

Проверить состояние:

```bash
ybook status
```

## Конфигурация

### Файл конфигурации и приоритеты

По умолчанию загружается `./ybook.toml`, если он существует. Другой файл:

```bash
ybook --config /path/to/ybook.toml status
ybook -c ./configs/other.toml all
```

`--config` может указывать на каталог — тогда используется `<каталог>/ybook.toml`. Явно указанный несуществующий файл — ошибка. Если файла нет и `--config` не задан, применяются значения по умолчанию, а относительные пути привязываются к текущему каталогу.

Приоритет значений:

1. флаги CLI;
2. переменные окружения (только документированные переопределения);
3. `ybook.toml`;
4. значения по умолчанию.

`Config.load()` читает TOML и применяет переменные окружения. Файл `.env` загружает **CLI** (до чтения конфига), а не библиотечный `Config.load()`; при использовании `ybook` как библиотеки переменные нужно задать самостоятельно.

Неизвестные ключи TOML **игнорируются** (`extra="ignore"`). Опечатка в имени ключа не вызовет ошибку, поэтому сверяйтесь с таблицами ниже. Ошибки TOML и валидации выводятся как `ConfigError` с понятным сообщением.

### Переменные окружения

`.env` ищется в каталоге конфига и в текущем каталоге. Порядок загрузки в CLI:

1. `<каталог конфига>/.env` (если `--config` задан; для файла — его каталог, для каталога — сам каталог);
2. `./.env` текущего каталога.

Оба файла загружаются с `override=False`: уже существующие переменные процесса имеют приоритет. Если переменная задана в обоих `.env`, побеждает файл из каталога конфига, потому что он загружается первым.

| Переменная | Назначение |
|---|---|
| `YOUTUBE_API_KEY` | ключ YouTube по умолчанию. Используется, если `youtube.api_key_env` указывает на `YOUTUBE_API_KEY`, а также как резерв, если переменная из `youtube.api_key_env` не задана. |
| `OPENAI_API_KEY` | ключ LLM по умолчанию, если `llm.api_key_env = "OPENAI_API_KEY"`. Нужен только при `llm.enabled = true`; с `--no-llm` не читается. |
| `YBOOK_LLM_API_KEY` | резервный ключ LLM, если переменная из `llm.api_key_env` не задана. Это **единственный** резерв для LLM; `OPENAI_API_KEY` автоматически не подставляется при другом имени. |
| `OPENAI_BASE_URL` | переопределяет `llm.base_url` (непустое значение). |
| `YBOOK_LLM_MODEL` | переопределяет `llm.model` (непустое значение). |
| `YBOOK_CHANNEL` | переопределяет `channel` (непустое значение). |

Других env-переопределений нет: пути, языки, `workers`, `include_shorts` и остальные параметры задаются только в TOML или флагами CLI. Ключи в TOML не записываются — там хранится только **имя** переменной (`api_key_env`).

### Разрешение путей

Ключи `data_dir` и `output_dir` описаны в разделе [«Секция paths»](#секция-paths). Относительные пути разрешаются от каталога файла `ybook.toml`; абсолютные остаются как есть; `~` раскрывается. Если конфига нет — от текущего рабочего каталога. Переданный в CLI `--out` разрешается от текущего рабочего каталога.

Автоматически создаются:

```text
<data_dir>/
<data_dir>/transcripts/
<data_dir>/cleaned/
<data_dir>/cache/llm/
<data_dir>/api/
<output_dir>/
```

Производные пути:

| Что | Путь |
|---|---|
| SQLite | `<data_dir>/state.sqlite` |
| Сырые и нормализованные расшифровки | `<data_dir>/transcripts/` |
| Очищенные или скопированные главы и аннотации | `<data_dir>/cleaned/` |
| Кэш ответов LLM | `<data_dir>/cache/llm/` |
| Отладочные снимки API | `<data_dir>/api/` |
| EPUB по умолчанию | `<output_dir>/book.epub` |

В SQLite пути к файлам сохраняются абсолютными. Это значит, что после переноса проекта со старой базой проверки файлов могут не найти старые пути: `transcripts`/`clean` пересоздадут файлы и обновят базу, а `build` без повторной очистки может пропустить главы. Для чистого переноса проще пересоздать `data/` (см. [«Сброс данных»](#сброс-данных)).

### Верхний уровень

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `channel` | string | `""` | URL канала, `@handle` или `UC...` ID. Нужен для `fetch`/`all`, если не передан `--channel`; можно переопределить `YBOOK_CHANNEL`. Пустое значение — ошибка при `fetch`/`all`. |

### Секция paths

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `data_dir` | path | `data` | Каталог данных и состояния. |
| `output_dir` | path | `out` | Каталог для EPUB по умолчанию. |

### Секция youtube

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `api_key_env` | string | `YOUTUBE_API_KEY` | Имя переменной окружения с ключом YouTube. Не может быть пустым. Если переменная пуста, используется `YOUTUBE_API_KEY` как резерв. |

### Секция transcripts

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `languages` | list[string] | `["en"]` | Приоритетный список языков субтитров. Должен содержать хотя бы один непустой код. CLI `--language` заменяет список одним языком. |
| `provider` | `auto` \| `youtube-transcript-api` \| `yt-dlp` | `auto` | Порядок источников. `auto` — сначала API, затем `yt-dlp`. |
| `cookies_from_browser` | string | `""` | Браузер для `--cookies-from-browser` в `yt-dlp` (например, `firefox`, `chrome`, `chromium`, `edge`, `brave`). Пусто — cookies не используются. |
| `workers` | int ≥ 1 | `3` | Число параллельных загрузок расшифровок. |
| `sleep_requests` | float ≥ 0 | `1.0` | Задержка в секундах перед обработкой каждого видео; дополнительно передаётся в `yt-dlp` как `--sleep-requests`. |
| `timeout_seconds` | int > 0 | `180` | Таймаут HTTP-сессии `youtube-transcript-api` и каждого запуска `yt-dlp`. |

### Секция llm

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `enabled` | bool | `true` | `false` — не вызывать LLM: `clean`/`all` копируют нормализованные расшифровки без изменений, не требуют ключа LLM и не генерируют аннотации. |
| `base_url` | string (`http://`/`https://`) | `https://api.openai.com/v1` | Базовый URL OpenAI-совместимого API. Код сам добавляет `/chat/completions`; этот путь указывать не нужно. Завершающий `/` убирается. |
| `api_key_env` | string | `OPENAI_API_KEY` | Имя переменной окружения с ключом LLM. Не может быть пустым. Резерв — `YBOOK_LLM_API_KEY`. |
| `model` | string | `gpt-4.1-mini` | Имя модели. Не может быть пустым. |
| `temperature` | float 0…2 | `0.2` | Температура; клиент отправляет её всегда. |
| `max_tokens` | int > 0 | `8192` | Лимит **выходных** токенов одного запроса. Имя поля в JSON задаётся `max_tokens_param`. |
| `max_words_per_chunk` | int ≥ 1 | `2500` | Максимальное число слов в одном чанке очистки. |
| `annotation_max_words` | int ≥ 1000 | `12000` | Максимум слов очищенной главы, отправляемых на аннотацию. Если текст длиннее, отправляются первая и последняя половины лимита. |
| `workers` | int ≥ 1 | `3` | Число параллельно очищаемых глав. |
| `timeout_seconds` | float > 0 | `180` | HTTP-таймаут одного запроса к LLM. |
| `max_tokens_param` | `max_tokens` \| `max_completion_tokens` | `max_tokens` | Имя поля лимита в JSON-запросе. |
| `input_cost_per_million` | float ≥ 0 | `0.0` | Цена входных токенов в USD за 1 млн. |
| `output_cost_per_million` | float ≥ 0 | `0.0` | Цена выходных токенов в USD за 1 млн. |
| `extra_headers` | table[string, string] | `{}` | Дополнительные HTTP-заголовки, например для OpenRouter. |

`enabled = false` включает режим без LLM. Флаги `--llm`/`--no-llm` у `clean` и `all` переопределяют конфиг: `--no-llm` работает даже при `enabled = true`, а `--llm` — даже при `enabled = false` (для него понадобится ключ LLM). В этом режиме уже готовые главы пропускаются, как и в LLM-режиме; `--force` перезаписывает их из нормализованных расшифровок и удаляет аннотации после успешного копирования. Остальные поля `[llm]` всё равно валидируются.

### Секция book

| Ключ | Тип | По умолчанию | Значение |
|---|---|---|---|
| `title` | string | `""` | Название книги. Пусто — берётся название канала. CLI `--title` переопределяет. |
| `author` | string | `""` | Автор. Пусто — название канала, затем название книги. CLI `--author` переопределяет. |
| `language` | string | `en` | Язык метаданных EPUB и язык аннотаций по умолчанию. Не может быть пустым. CLI `--language` переопределяет. |
| `description` | string | `""` | Описание книги. Пусто — описание канала. Отдельного CLI-флага нет. |
| `group_by_playlist` | bool | `true` | `true` — вложенное оглавление по плейлистам; `false` — одна часть «All chapters» в хронологическом порядке. `build --chronological` переопределяет. |
| `include_shorts` | bool | `true` | `false` — пропустить видео длительностью `0 < duration ≤ 180` секунд. Длительность `0` (неизвестна) не фильтруется. |
| `include_live` | bool | `true` | `false` — пропустить видео со статусом `live` или `upcoming`. Завершённые трансляции имеют `live_status = "none"` и остаются. |
| `annotations` | bool | `true` | Генерировать аннотации. `false` не генерирует новые; без `--force` существующие аннотации остаются. Любая успешная очистка с `--force` при выключенных аннотациях (`annotations = false` или `--no-annotations`) удаляет аннотацию. |

`book.annotations` управляет только генерацией. `build` включает любую непустую аннотацию, уже сохранённую в базе, независимо от текущего значения флага.

### Языки

Важно не путать три разные вещи:

| Что | Чем задаётся | Что не делает |
|---|---|---|
| Язык скачиваемых субтитров | `transcripts.languages`, `transcripts --language`, `all --language` | Не переводит существующий текст. |
| Язык аннотаций | `book.language`, `clean --language`, `all --language` | Не меняет язык очищенного текста. |
| Язык метаданных EPUB | `book.language`, `build --language`, `all --language` | Не переводит главы и уже готовые аннотации. |

`transcripts.languages` — список приоритетов. `--language` задаёт **один** язык и заменяет список. `clean --language` переопределяет только язык аннотаций. `build --language` меняет только метаданные книги. `all --language` передаёт один язык во все три стадии, поэтому это самый простой способ сделать книгу и аннотации на другом языке — при условии, что субтитры на нём существуют.

`--language` не переписывает уже готовые главы автоматически. `clean` без `--force` пропускает готовые главы, поэтому существующие аннотации останутся на прежнем языке. В LLM-режиме, чтобы перегенерировать аннотации, нужен `clean --force` (он также заново очистит текст) или предварительная инвалидация глав через `transcripts --language ...`.

### Валидация

- `transcripts.languages` не может быть пустым; пустые строки отбрасываются.
- `transcripts.workers` и `llm.workers` — не меньше 1.
- `transcripts.sleep_requests` — не меньше 0; `timeout_seconds` — больше 0.
- `llm.temperature` — от 0 до 2; `max_tokens` — больше 0; `max_words_per_chunk` — не меньше 1.
- `llm.enabled` — boolean. При `enabled = false` остальные поля `[llm]` всё равно проверяются по общим правилам: специального пропуска валидации нет.
- `llm.annotation_max_words` — не меньше 1000.
- `llm.base_url` должен начинаться с `http://` или `https://`; завершающий `/` удаляется.
- `llm.api_key_env`, `llm.model`, `youtube.api_key_env`, `book.language` не могут быть пустыми.
- `llm.max_tokens_param` — только `max_tokens` или `max_completion_tokens`.
- Цены не могут быть отрицательными.

### Примеры LLM-провайдеров

Код использует только OpenAI Chat Completions и `httpx`. Провайдер должен принимать `POST {base_url}/chat/completions` с `Authorization: Bearer <key>`.


```dotenv
OPENAI_API_KEY=sk-...
```

**OpenRouter**

```toml

api_key_env = "OPENROUTER_API_KEY"

extra_headers = { "HTTP-Referer" = "https://example.com", "X-Title" = "ybook" }
```

```dotenv
OPENROUTER_API_KEY=sk-or-...
```

**DeepSeek**

```toml

```

```dotenv
DEEPSEEK_API_KEY=...
```

**Локальная Ollama**

```dotenv

OPENAI_API_KEY=ollama
```

```bash
ollama serve
ollama pull llama3.1
```

Для локальной модели цена обычно нулевая; оставьте `input_cost_per_million = 0` и `output_cost_per_million = 0`. `OPENAI_API_KEY=ollama` нужен потому, что клиент требует непустой ключ, даже если локальный сервер его не проверяет.

`max_tokens` против `max_completion_tokens`: это **имя поля** в JSON, а не отдельный лимит. Если провайдер отвечает, что `max_tokens` не поддерживается, переключите:

```toml
max_tokens_param = "max_completion_tokens"
```

Значение `max_tokens` при этом остаётся тем же. Клиент всегда отправляет `temperature`; если конкретная модель её не принимает, потребуется доработка клиента.

### Стоимость

Если известны цены за миллион токенов:

```toml
[llm]
input_cost_per_million = 0.40
output_cost_per_million = 1.60
```

Стоимость считается по usage из ответа:

```text
cost_usd = prompt_tokens / 1_000_000 * input_cost_per_million
         + completion_tokens / 1_000_000 * output_cost_per_million
```

Поддерживаются оба варианта имён usage: `prompt_tokens`/`completion_tokens` и `input_tokens`/`output_tokens`. Результат сохраняется в `chapters.cost_usd`; там же лежат `tokens_in` и `tokens_out`. Если провайдер не вернул usage, счётчики будут нулевыми. Значения по умолчанию `0.0` означают «не считать стоимость», а не «бесплатно».

В режиме без LLM стоимость всегда нулевая: `clean` записывает `tokens_in = 0`, `tokens_out = 0`, `cost_usd = 0`, а `chapters.model` остаётся пустым. Запросов к провайдеру нет, поэтому и usage отсутствует.

`ybook` не печатает отдельный итоговый счёт стоимости в CLI. Посмотреть сумму можно, например, через `sqlite3`:

```bash
sqlite3 data/state.sqlite "SELECT ROUND(SUM(cost_usd), 6) AS usd FROM chapters;"
```

Стоимость главы накапливается в пределах одной обработки: чанки очистки плюс аннотация. Annotation-only backfill добавляет usage к существующим значениям; повторная очистка с `--force` пересчитывает стоимость заново.

### Один канал на один data-каталог

База рассчитана на **один канал**. `fetch` проверяет это: если в `data/state.sqlite` уже есть другой канал, команда завершится ошибкой, а не смешает книги. Для смены канала используйте чистый `data/` или удалите `data/state.sqlite` (и, желательно, старые файлы).

При повторном `fetch` того же канала удалённые на YouTube плейлисты, видео, расшифровки и главы вычищаются **из базы** (reconcile). Файлы в `data/transcripts/` и `data/cleaned/` при этом не удаляются и могут остаться «сиротами».

Если старая или смешанная база уже содержит несколько каналов, `clean` и `build` работают только с самым свежим каналом (по `fetched_at`) и предупреждают об остальных; главы других каналов не попадут в EPUB. `status` при этом показывает самый свежий канал, но счётчики читает по всей базе, поэтому в смешанной базе они могут включать старые каналы.

### Команда fetch

```bash
ybook fetch
ybook fetch --channel "https://www.youtube.com/@example"
ybook fetch --channel "@example"
ybook fetch --channel "UCxxxxxxxxxxxxxxxxxxxxxx"
```

| Опция | Тип | По умолчанию | Значение |
|---|---|---|---|
| `--channel` | string | `channel` из конфига | URL канала, `@handle` или `UC...` ID. Переопределяет конфиг. |

Что делает:

- разрешает канал и проверяет, что база не содержит другой канал;
- получает публичные плейлисты, плейлист загрузок и метаданные видео;
- сохраняет данные в SQLite;
- пишет снимки `data/api/channel.json`, `data/api/playlists.json`, `data/api/videos.json` (без API-ключа);
- удаляет из базы плейлисты/видео и связанные строки, которых больше нет на канале.

Вывод — таблица с названием канала, числом регулярных плейлистов, элементов загрузок и уникальных видео. У `fetch` нет `--limit` и `--force`: каждый запуск перечитывает канал целиком.

### Команда transcripts

```bash
ybook transcripts
ybook transcripts --language en --workers 4
ybook transcripts --limit 10
ybook transcripts --force
ybook transcripts --provider yt-dlp
ybook transcripts --provider youtube-transcript-api --limit 1
```

| Опция | Тип | По умолчанию | Значение |
|---|---|---|---|
| `--language`, `-l` | string | `transcripts.languages` (`["en"]`) | Один язык; заменяет список приоритетов. |
| `--limit` | int ≥ 1 | нет | Обработать не более N видео-кандидатов. |
| `--force`, `-f` | flag | выключено | Скачивать заново, даже если расшифровка уже есть. |
| `--workers` | int ≥ 1 | `transcripts.workers` (`3`) | Число параллельных загрузок. |
| `--provider` | `auto` \| `youtube-transcript-api` \| `yt-dlp` | `transcripts.provider` (`auto`) | Переопределить источник. Неверное значение — ошибка с кодом 2. |

Что делает:

- выбирает видео без успешной расшифровки или с языком, не подходящим под запрос;
- при смене языка инвалидирует старую очищенную главу **до** попытки скачивания;
- скачивает субтитры, сохраняет сырой файл и нормализованный текст;
- после успешного скачивания инвалидирует очищенную главу, даже если `--force` и текст не изменился;
- обновляет статусы `ok` / `skipped` / `failed`.

Вывод: `Processed`, `OK`, `Skipped`, `Failed`, `Already done`. Если обрабатывать нечего — `Nothing to do.` Статусы и причины сохраняются в SQLite; `skipped` — это нормальный результат для видео без субтитров.

`--force` не перезаписывает сырые файлы: при изменившемся ответе создаётся новый файл с суффиксом времени, а база начинает ссылаться на последний. Нормализованный `<video_id>.txt` перезаписывается атомарно.

### Команда clean

```bash
ybook clean
ybook clean --no-llm
ybook clean --limit 5
ybook clean --model gpt-4.1-mini
ybook clean --language ru
ybook clean --workers 2
ybook clean --force
ybook clean --force --no-llm
ybook clean --no-annotations
```

| Опция | Тип | По умолчанию | Значение |
|---|---|---|---|
| `--limit` | int ≥ 1 | нет | Обработать не более N глав-кандидатов; в LLM-режиме в лимит входят и главы, которым нужен только annotation backfill. |
| `--force`, `-f` | flag | выключено | Игнорировать кэш LLM и заново очищать главы; с `--no-llm` — перезаписать копии из расшифровок и удалить аннотации после успешного копирования. Аннотации перегенерируются, если они включены. |
| `--llm / --no-llm` | flag | `config.llm.enabled` (`true`) | `--no-llm` копирует нормализованные расшифровки без изменений и не требует ключа LLM; `--llm` включает LLM независимо от конфига. |
| `--model` | string | `llm.model` | Переопределить модель только для этого запуска. В режиме без LLM игнорируется. |
| `--workers` | int ≥ 1 | `llm.workers` (`3`) | Число параллельных очисток. В режиме без LLM игнорируется. |
| `--no-annotations` | flag | выключено | Не запрашивать аннотации. С `--force` удаляет аннотации после успешной очистки. В режиме без LLM аннотации и так не создаются. |
| `--language`, `-l` | string | `book.language` (`en`) | Язык **аннотаций**; текст главы не переводится. В режиме без LLM не используется. |

Что делает:

- берёт видео со статусом расшифровки `ok` и непустым `text_path`; файл читается при обработке, и если его нет, глава получает `failed`;
- **LLM-режим (по умолчанию):** очищает текст по чанкам, сохраняет `data/cleaned/<video_id>.txt`, проверяет качество (`cleaned` или `needs_review`) и генерирует `data/cleaned/<video_id>.annotation.txt`;
- **режим без LLM (`--no-llm`):** копирует нормализованный `data/transcripts/<video_id>.txt` в `data/cleaned/<video_id>.txt` без редактирования, ставит `cleaned`, не создаёт аннотацию и не обращается к LLM;
- в LLM-режиме, если глава уже готова, но аннотации нет, выполняет **annotation-only backfill**, не переочищая текст; в режиме без LLM backfill не запускается;
- в режиме без LLM ошибка на одном файле не прерывает запуск: остальные главы обрабатываются, а сбойная получает `failed`.

Вывод: `Processed`, `Cleaned`, `Needs review`, `Failed`, `Annotations`. `Annotations` — число глав с непустой аннотацией после обработки, а не число запросов к LLM. В режиме без LLM `Needs review` всегда `0`, а `Annotations` показывает только ранее сохранённые непустые аннотации — новые не создаются. Если обрабатывать нечего — `Nothing to do.`

Ключ LLM нужен только при включённом LLM: `clean` в LLM-режиме (когда `llm.enabled = true` или явно указан `--llm`, и не указан `--no-llm`) обращается к `POST {base_url}/chat/completions`, даже если указан `--no-annotations`. `clean --no-llm` копирует файлы локально, не требует ключа LLM и не делает сетевых запросов для очистки, но нормализованные расшифровки уже должны существовать (`ybook transcripts`). `build` остаётся полностью офлайн.

Без `--force` готовые главы пропускаются, поэтому `clean --no-llm` на существующей книге сохраняет уже очищенные главы и их аннотации. `clean --force --no-llm` заново копирует главы из расшифровок и удаляет их аннотации; аннотация удаляется только после успешного копирования, при ошибке старая аннотация остаётся.

### Команда build

```bash
ybook build
ybook build --out out/my-book.epub
ybook build --title "Моя книга" --author "Автор"
ybook build --language ru
ybook build --chronological
```

| Опция | Тип | По умолчанию | Значение |
|---|---|---|---|
| `--out`, `-o` | path | `<output_dir>/book.epub` | Путь к EPUB; относительный путь считается от текущего каталога. |
| `--title` | string | `book.title`, затем название канала | Название книги. |
| `--author` | string | `book.author`, затем название канала, затем название книги | Автор. |
| `--language`, `-l` | string | `book.language` (`en`) | Язык метаданных EPUB; текст не переводится. |
| `--chronological` | flag | выключено | Игнорировать плейлисты и собрать одну часть в порядке публикации. |

Что делает:

- работает **без сети** и без API-ключей;
- читает SQLite и файлы из `data/cleaned/`;
- берёт только главы со статусами `cleaned` и `needs_review`, у которых существует непустой файл;
- фильтрует по текущему каналу (самому свежему в базе) и по `include_shorts`/`include_live`;
- собирает EPUB и атомарно заменяет целевой файл.

Вывод: `Path`, `Parts`, `Chapters`. Если глав нет — ошибка `No cleaned chapters are available...`. Подробная структура — в разделе [«Сборка EPUB»](#сборка-epub).

### Команда all

```bash
ybook all
ybook all --no-llm
ybook all --channel "https://www.youtube.com/@example"
ybook all --out out/book.epub --language en
ybook all --limit 5 --force
ybook all --provider yt-dlp
ybook all --no-annotations
```

| Опция | Тип | По умолчанию | Значение |
|---|---|---|---|
| `--channel` | string | `channel` из конфига | URL/хэндл/ID канала. |
| `--out`, `-o` | path | `<output_dir>/book.epub` | Путь к EPUB; относительный — от текущего каталога. |
| `--language`, `-l` | string | не задан: `transcripts.languages` для субтитров, `book.language` для аннотаций и метаданных | Один язык для расшифровок, аннотаций и метаданных книги. |
| `--limit` | int ≥ 1 | нет | Не более N видео **на каждой** стадии `transcripts` и `clean`. `fetch` не ограничивается. |
| `--force`, `-f` | flag | выключено | Передаётся в `transcripts` и `clean`. |
| `--llm / --no-llm` | flag | `config.llm.enabled` (`true`) | `--no-llm` копирует расшифровки без изменений на стадии `clean` и не требует ключа LLM; `--llm` включает LLM независимо от конфига. |
| `--provider` | `auto` \| `youtube-transcript-api` \| `yt-dlp` | `transcripts.provider` | Только для стадии расшифровок. |
| `--title` | string | `book.title`/канал | Название книги. |
| `--author` | string | `book.author`/канал | Автор. |
| `--chronological` | flag | выключено | Одна хронологическая часть. |
| `--no-annotations` | flag | выключено | Не запрашивать аннотации на стадии `clean`. В режиме без LLM аннотации и так не создаются. |

`all` последовательно вызывает `fetch → transcripts → clean → build`. У него нет отдельных `--model` и `--workers`: модель и число воркеров берутся из `[llm]`, а воркеры расшифровок — из `[transcripts]`. `--force` действует на расшифровки и очистку, но не на `fetch`; `build` и так всегда пересобирает файл. В конце печатается сводка: канал, счётчики расшифровок и очистки, финальные счётчики базы и путь к EPUB.

`all` требует ключ YouTube (для `fetch`). Ключ LLM нужен только при включённом LLM: в режиме `--no-llm` (или при `llm.enabled = false`) стадия `clean` копирует расшифровки локально. Отдельным командам нужны только их ключи: `fetch` — YouTube, `clean` в LLM-режиме — LLM, `transcripts` и `build` — ни тот ни другой.

`--limit` — это лимит **кандидатов на стадию**, а не гарантия числа глав. Стадии выбирают кандидатов независимо, поэтому это не обязательно одни и те же видео. Например, при `--limit 3` три видео могут получить `skipped`, и в книгу попадут только те главы, которые реально удалось очистить.

### Команда status

```bash
ybook status
ybook --config other.toml status
```

Опций нет. Показывает:

- название канала (или `No channel fetched yet.`);
- путь к SQLite;
- число регулярных плейлистов, видео;
- расшифровки по статусам `ok` / `skipped` / `failed`;
- главы по статусам `cleaned` / `needs_review` / `failed`;
- число аннотаций.

`status` не ходит в сеть и не требует ключей. Если базы нет, она будет создана пустой. В смешанной базе счётчики читаются по всем каналам, хотя отображается самый свежий канал.

### Коды возврата и логи

| Код | Когда |
|---|---|
| `0` | Команда успешно завершена (включая `Nothing to do.`). |
| `1` | Ожидаемая ошибка: конфигурация, сеть, квота, LLM, отсутствие глав и т.п. Печатается `Error: ...` без traceback. |
| `2` | Неверное значение `--provider` или ошибка разбора аргументов CLI. |

Логи по умолчанию — INFO, с `--verbose`/`-v` — DEBUG. Шумные логи `httpx`, `httpcore`, `urllib3` приглушены. Ожидаемые ошибки не показывают traceback; неожиданные исключения — показывают, потому что сигнализируют о баге.

## Как работает конвейер

### Схема

```text
ybook all
   │
   ├─ fetch ──────────► YouTube Data API v3
   │                      ├─ channels.list
   │                      ├─ playlists.list
   │                      ├─ playlistItems.list
   │                      └─ videos.list
   │                    ──► SQLite + data/api/*.json
   │
   ├─ transcripts ────► youtube-transcript-api ─┐
   │                      └─ yt-dlp (fallback)  ├─► data/transcripts/<id>.json|.vtt
   │                                            └─► data/transcripts/<id>.txt
   │
   ├─ clean ──┬───────► LLM включён (по умолчанию)
   │          │           ├─ очистка по чанкам ──► data/cleaned/<id>.txt
   │          │           └─ аннотация ──────────► data/cleaned/<id>.annotation.txt
   │          │
   │          └───────► LLM выключен (`--no-llm`)
   │                      └─ копия без изменений ─► data/cleaned/<id>.txt
   │
   └─ build ──────────► SQLite + data/cleaned/*.txt ──► out/book.epub
```

Стадии можно запускать отдельно. `fetch` и `transcripts` требуют сети и ключа YouTube; `clean` по умолчанию требует сети и ключа LLM, а `clean --no-llm` работает локально с уже скачанными расшифровками. `build` — полностью офлайн.

### YouTube: канал и метаданные

#### Поддерживаемые формы ссылок

| Ввод | Обработка |
|---|---|
| `@example` | `channels.list?forHandle=example` |
| `https://www.youtube.com/@example` | то же |
| `https://www.youtube.com/@example/videos` | то же; хвост `/videos` игнорируется |
| `https://m.youtube.com/@example/shorts` | то же |
| `UC...` | `channels.list?id=UC...` |
| `https://www.youtube.com/channel/UC...` | то же |
| `https://www.youtube.com/channel/UC.../videos` | то же |
| `https://www.youtube.com/c/SomeName` | `forHandle` → `forUsername` → `search.list` |
| `https://www.youtube.com/user/SomeName` | `channels.list?forUsername=SomeName` |
| `youtube.com/@example` без схемы | добавляется `https://` |

Отклоняются с понятной ошибкой: пустая строка, `youtu.be/...`, ссылки на `watch`, `playlist`, `embed`, `live`, `shorts/<video>`, не-YouTube хосты, голое имя без `@`, корень `https://www.youtube.com/` без пути. Проверка формы выполняется до обращения к API.

#### Разрешение канала и квота

| Шаг | Endpoint | Стоимость |
|---|---|---|
| Канал по ID, `@handle` или username | `channels.list` | 1 единица |
| Список плейлистов | `playlists.list` | 1 единица за страницу (до 50 плейлистов) |
| Элементы плейлиста | `playlistItems.list` | 1 единица за страницу (до 50 элементов) |
| Метаданные видео | `videos.list` | 1 единица за пачку до 50 ID |
| Поиск канала для `/c/...` | `search.list` | 100 единиц (только fallback) |

Для `/c/...` порядок такой: `forHandle` (1), затем `forUsername` (1), затем `search.list` (100) и `channels.list` по найденному ID (1). Худший случай — около 103 единиц только на разрешение канала. Дневная квота по умолчанию — 10 000 единиц; сброс обычно происходит в полночь по тихоокеанскому времени. Ответы API не кэшируются, поэтому каждый `fetch` снова расходует квоту.

#### Перечисление данных

- `playlists.list` и `playlistItems.list` идут по `nextPageToken`; повторный токен считается ошибкой API, а не бесконечным циклом.
- Из плейлистов берутся только публичные; `Deleted video` и `Private video` пропускаются (сравнение заголовка без учёта регистра). Записи без `videoId` также пропускаются.
- Плейлист загрузок берётся из `contentDetails.relatedPlaylists.uploads`, сохраняется с `kind="uploads"` и `position=-1`. Если его нет, пишется предупреждение, но регулярные плейлисты обрабатываются.
- Все ID из загрузок и регулярных плейлистов объединяются и дедуплицируются; `videos.list` вызывается пачками до 50 ID.
- ISO-8601 длительность (`PT1H2M3S`, `P1DT2H`, `PT1.5S`) переводится в секунды. Неразборчивая длительность даёт `0` и предупреждение.
- Сохраняются `defaultAudioLanguage` и `liveBroadcastContent` (`none`, `live`, `upcoming`).
- После получения метаданных `reconcile_channel` удаляет из базы плейлисты/видео и связанные расшифровки/главы, которых не было в новом ответе. Файлы на диске не удаляются.

#### Повторы и ошибки API

- `429`, `5xx`, а также `403` с `rateLimitExceeded`/`userRateLimitExceeded` повторяются до 4 попыток с экспоненциальной задержкой (0.5–8 с).
- `403 quotaExceeded`/`dailyLimitExceeded` **не** повторяется: выбрасывается `QuotaExceededError` с понятным сообщением.
- `keyInvalid` даёт сообщение о неверном или ограниченном ключе.
- Сетевые ошибки `httpx` повторяются; ключ вырезается из текста ошибки.
- HTTP-таймаут клиента YouTube — 30 секунд (не настраивается через TOML).

### Субтитры

#### Цепочка провайдеров

| `provider` | Порядок |
|---|---|
| `auto` (по умолчанию) | сначала `youtube-transcript-api`, затем `yt-dlp` |
| `youtube-transcript-api` | только API |
| `yt-dlp` | только `yt-dlp` |

Успех первого провайдера останавливает цепочку. Если оба не дали текста, итоговый статус — `failed`, когда хотя бы один провайдер сообщил об ошибке; иначе `skipped`. Сообщение об ошибке содержит причины от обоих провайдеров.

#### youtube-transcript-api

- Создаётся `YouTubeTranscriptApi` с `requests`-сессией, которой задан единый таймаут `transcripts.timeout_seconds`.
- `api.list(video_id)` возвращает доступные дорожки; выбираются те, чей `language_code` соответствует запрошенным языкам.
- Приоритет: **ручная дорожка важнее сгенерированной**, даже если сгенерированная идёт раньше по языковому списку. Внутри одного типа — приоритет языка; при равенстве — порядок дорожек в ответе API.
- Сохраняется сырой JSON: `video_id`, `source`, `language`, `language_code`, `is_generated`, `fetched_at`, `snippets`.
- Нормализованный текст собирается из `snippets` и сохраняется в `<video_id>.txt`.
- Пустой текст — `skipped`.

Типичные ошибки:

| Ситуация | Статус |
|---|---|
| Субтитры отключены / нет дорожки на запрошенном языке | `skipped` |
| Видео недоступно, приватное, age-restricted | `skipped` |
| IP/запрос заблокирован, требуется PO token, YouTube request failed | `failed` |
| Неверный video ID, прочие ошибки API | `failed` |
| Пустой текст после нормализации | `skipped` |

#### yt-dlp

`yt-dlp` вызывается как `python -m yt_dlp` (тем же интерпретатором, что и `ybook`) с `--skip-download`, `--no-playlist`, `--no-progress`, `--retries 3`, `--socket-timeout 30` и `--sleep-requests <sleep_requests>`. Аудио не скачивается.

Сначала выполняется проход за **ручными** субтитрами:

```text
--write-subs --sub-langs "en.*,ru.*" --sub-format vtt
```

Если файлов нет, выполняется проход за **авто**:

```text
--write-auto-subs --sub-langs "en.*-orig,ru.*-orig" --sub-format vtt
```

Для авто-прохода принимаются только файлы, язык которых заканчивается на `-orig`. Машинные переводы (`en.vtt` для неанглийского видео и т.п.) отклоняются. Для ручного прохода допускается один файл без языкового тега — ему приписывается первый запрошенный язык.

Таймаут `timeout_seconds` применяется к **каждому** запуску `yt-dlp` (ручному и авто). Если задан `cookies_from_browser`, добавляется `--cookies-from-browser <браузер>`. Cookies используются только для `yt-dlp`; у `youtube-transcript-api` в этом проекте нет настройки cookies.

Ошибки:

| Ситуация | Статус |
|---|---|
| Найден ручной или авто-файл | `ok` |
| Субтитров нет | `skipped` |
| Только переведённая авто-дорожка без `-orig` | `skipped` |
| Bot check / 429 / «Sign in to confirm…» | `failed` с подсказкой |
| Таймаут или ненулевой код возврата | `failed` |

#### VTT-парсер

`data/transcripts/<video_id>.vtt` разбирается в `VTTCue`:

- удаляются теги, HTML-сущности раскрываются, а служебные блоки `WEBVTT`, `NOTE`, `STYLE`, `REGION` пропускаются;
- `<v Speaker>` превращается в `Speaker:`;
- звуковые пометки `[Music]`, `[Applause]`, `[Музыка]`, `[Аплодисменты]`, `♪` и подобные удаляются, если в кью нет другого текста;
- `[unclear]` сохраняется;
- «бегущие» авто-субтитры склеиваются: точные дубликаты, расширения предыдущей фразы и перекрывающиеся повторы (минимум 2 слова, либо 1 слово при пересечении по времени в пределах 0.1 с) объединяются;
- повторяющаяся подпись спикера не дублируется;
- итоговый текст нормализуется в одну строку с одним пробелом.

#### Языковое соответствие

Запрос `en` принимает сохранённые `en`, `en-US`, `en-orig` и другие варианты с префиксом `en-`. Запрос `ru` **не** принимает `en`. Запрос `en-US` не принимает просто `en` (нужна более конкретная дорожка). Пустой сохранённый язык никогда не считается подходящим.

| Сохранено | Запрошено | Подходит |
|---|---|---|
| `en` | `en` | да |
| `en-US` | `en` | да |
| `en-orig` | `en` | да |
| `ru` | `en` | нет |
| `en` | `ru` | нет |
| `en` | `en-US` | нет |
| `ru-RU` | `ru` | да |

Если сохранённая расшифровка не подходит по языку, она считается неполной: `transcripts` попробует скачать заново, а старая очищенная глава будет инвалидирована. Подробности — в разделе [«Смена языка и инвалидация»](#смена-языка-и-инвалидация).

### Очистка LLM

#### Режим без LLM

Включается через `[llm] enabled = false` или флаги `--no-llm` у `clean`/`all`. Флаги имеют приоритет над конфигом: `--no-llm` работает даже при `enabled = true`, а `--llm` — даже при `enabled = false`.

В этом режиме `clean`:

- читает нормализованный `data/transcripts/<video_id>.txt`;
- копирует текст без редактирования в `data/cleaned/<video_id>.txt` (содержимое не меняется; при записи добавляется завершающий перевод строки);
- ставит главе статус `cleaned`;
- записывает `tokens_in = 0`, `tokens_out = 0`, `cost_usd = 0`, а `chapters.model` оставляет пустым (`NULL`);
- не создаёт аннотацию и не запускает annotation-only backfill;
- не выполняет quality guard и не выставляет `needs_review`;
- не требует ключа LLM и не делает запросов к `/chat/completions`: на стадии очистки текст не покидает машину.

Идемпотентность: готовые главы пропускаются, как и в LLM-режиме. `clean --no-llm` на существующей книге сохраняет уже очищенные главы и их аннотации. `clean --force --no-llm` заново копирует главы из расшифровок и удаляет их аннотации; аннотация удаляется только после успешного копирования, при ошибке старая аннотация сохраняется.

Если расшифровка отсутствует, пуста или не читается, глава получает `failed` и исключается из EPUB. Существующие аннотация, предупреждения, токены, стоимость и модель при этом сохраняются. Старый `data/cleaned/<video_id>.txt` (если он был) остаётся на диске как страховочная копия, но база на него больше не ссылается, поэтому `build` его не включает. Ошибка одного файла не прерывает весь запуск: сбои изолируются по главам.

`book.annotations` и `--no-annotations` принимаются, но в режиме без LLM аннотации и так не генерируются, а annotation-only backfill не запускается. Уже существующие непустые аннотации `build` включает, пока их не удалить через `clean --force --no-llm`.

`all --no-llm` выполняет `fetch → transcripts → clean (копия) → build` и требует только ключ YouTube.

#### Чанкование

В LLM-режиме текст расшифровки делится на чанки по `llm.max_words_per_chunk` (по умолчанию 2500 слов). Приоритет границ: абзац → предложение → отдельное слово. Слишком маленький последний чанк (меньше 10% лимита, но не более 100 слов) перебалансируется с предыдущим, чтобы LLM не получала обрывок. Каждый чанк очищается отдельным запросом; результаты соединяются через пустую строку и нормализуются в абзацы.

#### Кэш

Ключ кэша — SHA-256 от JSON:

```text
prompt_version, model, base_url, temperature, max_tokens,
max_tokens_param, context (channel, playlist, video_title), chunk
```

Кэш лежит в `data/cache/llm/<sha256>.txt` (текст ответа) и `<sha256>.json` (usage и стоимость). Он не включает API-ключ, `extra_headers`, цены и `max_words_per_chunk` (последнее влияет на текст чанка, поэтому фактически меняет ключ через `chunk`). Смена модели, `base_url`, температуры, лимита, имени параметра или версии промпта даёт новые ключи.

`clean` использует кэш, `--force` игнорирует чтение кэша, но всё равно записывает новые ответы. Если вы меняете текст промпта, **увеличьте `PROMPT_VERSION`** в `src/ybook/prompts.py`, иначе старые ответы будут переиспользованы.

#### Правила промпта

Системный промпт просит бережного редактора:

- сохранять смысл, факты, примеры, числа, имена и голос автора;
- добавлять пунктуацию, заглавные буквы и абзацы;
- убирать только слова-паразиты, повторы и ложные начала;
- исправлять только очевидные ошибки ASR; если слово непонятно — писать `[unclear]`, а не угадывать;
- не сокращать, не добавлять факты, не цензурировать, не делать заголовки/списки/комментарии;
- не переводить: вернуть текст на языке оригинала;
- вернуть только текст, без кавычек, code fence и преамбул.

Промпты написаны на английском намеренно: так модель получает однозначные правила независимо от языка расшифровки. Язык вывода задаётся входным текстом (очистка) или параметром `language` (аннотация).

#### Повторы и проверки качества

- При пустом ответе или ответе с мета-комментарием («As an AI…», «Here is the text…», «Конечно, вот текст…») делается **один** повторный запрос с более строгой инструкцией.
- Если после повтора текст снова пустой — глава `failed`.
- Если после повтора остался мета-комментарий — глава `needs_review` с предупреждением.
- HTTP `429`, `5xx` и сетевые ошибки повторяются до 4 попыток с экспоненциальной задержкой; прочие `4xx` — постоянная ошибка.
- Ответ очищается от code fence, заголовков и типичных преамбул.

Проверки качества (`chapters.warnings`):

| Проверка | Предупреждение |
|---|---|
| Соотношение слов | Вне диапазона `0.75–1.30` от исходника. |
| Числа | В результате не хватает числовых токенов из исходника (ISO-даты игнорируются, разделители нормализуются). |
| Мета-комментарии | В первых 1000 символах найдены служебные фразы. |
| Обрыв | Текст заканчивается без терминальной пунктуации и на слово. |
| Пустота | Пустой результат (обычно приводит к `failed` раньше). |

Статусы главы:

| Статус | Значение | Попадает в EPUB |
|---|---|---|
| `cleaned` | Проверки пройдены, предупреждений нет. | Да |
| `needs_review` | Есть предупреждения (длина, числа, мета, обрыв) или не удалась аннотация. | Да, с предупреждениями в базе |
| `failed` | LLM не вернул пригодный текст; новый файл главы не записан, глава не включается в книгу. | Нет |

### Аннотации

В режиме без LLM (`llm.enabled = false` или `--no-llm`) аннотации не генерируются, а annotation-only backfill не запускается. Существующие непустые аннотации сохраняются и попадают в `build`, пока их не удалить через `clean --force --no-llm`.

- Аннотация генерируется из **очищенного** текста главы, а не из сырой расшифровки.
- Если текст длиннее `llm.annotation_max_words`, в запрос уходят первая и последняя половины лимита, разделённые маркером `\n\n[...]\n\n`; середина не отправляется.
- Промпт просит 2–4 предложения на языке `language`, только по фактам из текста, без заголовков, списков, кавычек и преамбул.
- Ответ очищается от заголовков, списков, кавычек и типичных преамбул.
- Если получилось меньше двух предложений, делается один более строгий запрос. Если после повтора всё ещё меньше двух, текст всё равно принимается — жёсткой блокировки нет.
- Если предложений больше четырёх, остаются первые четыре.
- Если аннотация пустая после всех попыток — глава остаётся в книге, получает `needs_review`, предупреждение `annotation failed`, а файл аннотации удаляется. Если это была повторная очистка, старая аннотация тоже удаляется: новая не сгенерирована.
- В LLM-режиме следующий `clean` без `--force` выполняет **annotation-only backfill**: читает готовый `data/cleaned/<id>.txt`, генерирует только аннотацию, добавляет usage к существующим токенам/стоимости и снимает предупреждение `annotation failed`. Если других предупреждений нет, статус возвращается в `cleaned`; иначе остаётся `needs_review`.
- В LLM-режиме, если очистка с `--force` падает, старая аннотация сохраняется в базе, но глава получает `failed` и не попадает в книгу.
- Аннотации не кэшируются отдельно: при `--force` они генерируются заново.

### Сборка EPUB

EPUB пишется вручную на стандартной библиотеке, без `ebooklib` и `pandoc`:

```text
mimetype                       (первый файл, ZIP_STORED, без сжатия)
META-INF/container.xml
OEBPS/content.opf
OEBPS/nav.xhtml                (вложенное EPUB 3 TOC + landmarks)
OEBPS/toc.ncx                  (вложенные navPoint/playOrder)
OEBPS/style.css
OEBPS/text/title.xhtml
OEBPS/text/about.xhtml
OEBPS/text/part-001.xhtml
OEBPS/text/chapter-001.xhtml
...
```

- **Обложки нет**; изображений в пакете нет.
- `mimetype` — первый файл архива, хранится без сжатия; остальные файлы сжимаются.
- Титульная страница: название, автор/канал, «Compiled from YouTube transcripts», дата, ссылка на источник.
- About: описание (из `book.description` или канала), источник, число глав/частей, пометка о том, что тексты — отредактированные расшифровки.
- Часть: заголовок плейлиста и описание, обрезанное до 600 символов по границе слова.
- Глава: заголовок, дата публикации, длительность, ссылка «Watch on YouTube», аннотация курсивом, абзацы текста.
- Все тексты экранируются; недопустимые для XML символы удаляются.
- Абзацы рендерятся через `to_paragraphs`: блоки разделяются пустой строкой; блок длиннее 5 предложений делится на группы по 5; длинный блок без пунктуации — на группы примерно по 180 слов.
- ZIP-записи имеют фиксированные timestamps (`1980-01-01`), а UUID книги детерминирован: `uuid5` от `channel_id` (или URL/автора) и названия. При этом `dc:date`/`dcterms:modified` и дата на титульной странице зависят от времени сборки, поэтому байт-в-байт файлы разных запусков могут отличаться.
- Запись атомарная: временный файл в каталоге назначения заменяется через `os.replace`.
- EPUB не проверяется встроенным `epubcheck`; для валидации используйте внешнюю утилиту.

## Группировка книги и дубликаты

По умолчанию (`book.group_by_playlist = true` и без `--chronological`) книга группируется по **регулярным** плейлистам канала. Плейлист загрузок (`kind="uploads"`) в оглавление как часть не попадает.

Алгоритм:

1. Берутся только главы, готовые к сборке, прошедшие фильтры `include_shorts`/`include_live` и принадлежащие текущему каналу.
2. Для каждого видео среди всех регулярных плейлистов выбирается **самый специфичный** плейлист. Критерий — минимум по кортежу:
   - `effective_item_count` — `item_count` из API, а если он равен `0`, фактическое число элементов в базе;
   - `playlist_position` — позиция плейлиста на канале;
   - `playlist_id` — детерминированный tie-break.
3. Видео попадает ровно в одну часть, поэтому дубликаты исключаются.
4. Части идут в порядке позиции плейлиста; главы внутри части — в порядке позиции элемента плейлиста.
5. Пустые плейлисты пропускаются.
6. Видео, которых нет ни в одном регулярном плейлисте, попадают в последнюю часть **«Other videos»** в хронологическом порядке.

Пример: видео `v1` есть в маленьком плейлисте A (2 элемента) и большом B (100 элементов) — оно попадёт в A. Видео `v2` только в B — в B. Видео `v3` только в загрузках — в «Other videos». Плейлист C без глав будет пропущен. Так «плейлист всех видео» не поглощает книгу.

Хронологический режим:

- `book.group_by_playlist = false` или `ybook build --chronological`;
- все готовые главы сортируются по `published_at`, затем по `video_id`;
- создаётся одна часть **«All chapters»**;
- плейлисты, «Other videos» и их порядок игнорируются.

Фильтры применяются до группировки:

- `include_shorts = false` пропускает `0 < duration_seconds ≤ 180`; неизвестная длительность `0` остаётся;
- `include_live = false` пропускает `live_status` `live` и `upcoming`; завершённые трансляции (`none`) остаются;
- фильтры влияют только на сборку EPUB, но не удаляют главы из базы.

Похожая логика выбора самого специфичного плейлиста (по числу элементов и позиции) используется для контекста промпта очистки: в `ChapterContext.playlist` попадает название выбранного регулярного плейлиста или `Uploads`, если видео нет в регулярных плейлистах.

## Данные, SQLite и идемпотентность

### Каталоги

По умолчанию:

```text
data/
├── state.sqlite          # SQLite: каналы, плейлисты, видео, расшифровки, главы
├── api/                  # отладочные JSON-снимки YouTube API (без ключа)
│   ├── channel.json
│   ├── playlists.json
│   └── videos.json
├── transcripts/          # сырые .json/.vtt и нормализованные .txt
│   ├── <video_id>.json
│   ├── <video_id>.vtt
│   ├── <video_id>.<timestamp>.json|.vtt
│   └── <video_id>.txt
├── cleaned/              # очищенные/скопированные тексты и аннотации
│   ├── <video_id>.txt
│   └── <video_id>.annotation.txt
└── cache/llm/            # кэш ответов LLM
    ├── <sha256>.txt
    └── <sha256>.json
out/
└── book.epub
```

| Файл | Что содержит | Перезаписывается |
|---|---|---|
| `data/transcripts/<id>.json` | Сырой ответ `youtube-transcript-api`: метаданные и `snippets`. | Никогда; при изменении — новый файл с timestamp. |
| `data/transcripts/<id>.vtt` | Сырой VTT от `yt-dlp`. | Никогда; при изменении — новый файл с timestamp. |
| `data/transcripts/<id>.txt` | Нормализованный текст расшифровки. | Атомарно при успешном скачивании. |
| `data/cleaned/<id>.txt` | Очищенная глава; в режиме без LLM — копия нормализованной расшифровки. | Атомарно при успешной очистке или копировании; удаляется при инвалидации. |
| `data/cleaned/<id>.annotation.txt` | Аннотация главы; в режиме без LLM не создаётся. | Атомарно при генерации; удаляется, если аннотации нет. |
| `data/cache/llm/<sha>.txt` | Текст ответа LLM для чанка. | При новом ответе с тем же ключом. |
| `data/cache/llm/<sha>.json` | Usage и стоимость чанка. | То же. |
| `data/api/*.json` | Отладочные снимки канала, плейлистов, видео. | При каждом `fetch`; ключ не включается. |

Сырые файлы не удаляются и не перезаписываются: при `--force` и изменившемся ответе рядом появляется файл с суффиксом времени, а в базе сохраняется путь к последнему. Это позволяет сравнивать ответы провайдеров, но каталог может расти.

### Схема SQLite

Создаётся в `data/state.sqlite` при первом обращении; миграций и таблицы версий нет. Схема — `CREATE TABLE IF NOT EXISTS` в `src/ybook/db.py:16`.

| Таблица | Колонки | Назначение |
|---|---|---|
| `channels` | `id`, `title`, `description`, `url`, `uploads_playlist_id`, `fetched_at` | Каналы. `get_channel()` возвращает самый свежий по `fetched_at`. |
| `playlists` | `id`, `channel_id`, `title`, `description`, `item_count`, `position`, `kind`, `fetched_at` | Плейлисты; `kind` — `regular` или `uploads`, у загрузок `position = -1`. |
| `videos` | `id`, `channel_id`, `title`, `description`, `published_at`, `duration_seconds`, `default_audio_language`, `live_status`, `fetched_at` | Метаданные видео. |
| `playlist_items` | `playlist_id`, `video_id`, `position`; PK `(playlist_id, video_id)` | Членство видео в плейлисте. |
| `transcripts` | `video_id`, `language`, `is_generated`, `source`, `raw_path`, `text_path`, `status`, `error`, `fetched_at` | Состояние расшифровки. |
| `chapters` | `video_id`, `cleaned_path`, `annotation`, `status`, `error`, `warnings`, `tokens_in`, `tokens_out`, `cost_usd`, `model`, `updated_at` | Состояние очистки и аннотации. |

Индексы: `videos(channel_id)`, `playlist_items(video_id)`, `chapters(status)`, `transcripts(status)`.

Особенности:

- `playlist_items` заменяется целиком при каждом `fetch` плейлиста.
- `warnings` — JSON-массив строк; `error` — последняя ошибка; `model` — модель последней обработки (в режиме без LLM пустое значение).
- `chapters.cleaned_path` может быть `NULL` у `failed`; `build` такие главы не берёт.
- `chapters.cost_usd` — стоимость в USD; `tokens_in`/`tokens_out` — usage.
- Внешних ключей в схеме нет; связи и очистку дочерних строк обеспечивает код (`reconcile_channel`).
- В базе хранятся абсолютные пути к файлам.

### Статусы

| Таблица | Статус | Значение |
|---|---|---|
| `transcripts` | `ok` | Расшифровка получена; `text_path` указывает на файл, наличие проверяется при повторном запуске. |
| | `skipped` | Субтитров на нужном языке нет, они отключены или видео недоступно. |
| | `failed` | Сетевая ошибка, блокировка, таймаут, ошибка провайдера. |
| `chapters` | `cleaned` | Очистка прошла, предупреждений нет; в режиме без LLM — расшифровка скопирована без изменений. |
| | `needs_review` | Есть предупреждения (только LLM-режим); глава включается в книгу. |
| | `failed` | Пригодного текста нет (в режиме без LLM — расшифровка отсутствует, пуста или не читается); глава не включается в книгу. |

`skipped` и `failed` у расшифровок повторяются при следующем запуске `transcripts`. `failed` у главы повторяется при следующем `clean`. В режиме без LLM `cleaned` означает только успешное копирование: текст не редактировался, аннотации нет.

### Идемпотентность и повторные запуски

| Команда | Без `--force` | С `--force` | `--limit` |
|---|---|---|---|
| `fetch` | Обновляет метаданные, заменяет членство, удаляет устаревшие строки. | Не применимо. | Не применимо; канал читается целиком. |
| `transcripts` | Пропускает `ok` с существующим `.txt` и подходящим языком; `skipped`/`failed` повторяет. | Заново скачивает выбранных; после успеха инвалидирует очищенную главу. | Ограничивает число кандидатов после отсева готовых. |
| `clean` | Пропускает готовые главы; в LLM-режиме при отсутствии аннотации делает backfill. В режиме без LLM копирует недостающие главы без аннотаций. | Игнорирует кэш, переочищает; аннотации перегенерирует. С `--no-llm` перезаписывает копии из расшифровок и удаляет аннотации после успешного копирования. | Ограничивает число кандидатов. |
| `build` | Всегда пересобирает EPUB. | Не применимо. | Не применимо. |
| `all` | Выполняет все стадии; лимиты и force применяются к `transcripts`/`clean`. | `--force` передаётся в `transcripts` и `clean`. | `--limit` действует на каждой из двух стадий отдельно. |

Дополнительно:

- `fetch` идемпотентен по данным, но не по квоте: каждый запуск снова обращается к API.
- `transcripts` проверяет не только статус, но и наличие файла и соответствие языка. Если файл удалён, расшифровка будет скачана заново.
- `clean` проверяет статус и наличие очищенного файла. Если файл удалён, глава обрабатывается заново.
- `clean` без `--force` в LLM-режиме обрабатывает главу с отсутствующей аннотацией, не переочищая текст.
- `build` не меняет базу и всегда атомарно заменяет целевой EPUB.
- `--force` у `transcripts` **не** перезаписывает сырые файлы; нормализованный `.txt` перезаписывается.
- `--force` у `clean` при выключенных аннотациях (`--no-annotations` или `book.annotations = false`) очищает аннотации только после успешной очистки; при падении самой очистки старая аннотация остаётся в базе.
- В режиме без LLM `--force` удаляет аннотацию только после успешного копирования; если чтение расшифровки или запись главы не удались, старая аннотация сохраняется. Глава при этом получает `failed`, а старый `data/cleaned/<id>.txt` остаётся на диске, но `build` его не использует.
- `--limit` считает кандидатов, а не успешные главы. При `--limit 3` книга может получить меньше трёх глав.

### Смена языка и инвалидация

Смена языка — самая чувствительная операция:

1. `transcripts --language ru` (или `all --language ru`) заменяет список языков одним `ru`.
2. Для видео, у которых уже есть `ok`-расшифровка на неподходящем языке, **до** попытки скачивания удаляются строка главы, `data/cleaned/<id>.txt` и `data/cleaned/<id>.annotation.txt`.
3. Если новая расшифровка получена — сохраняется `ru`, глава снова инвалидируется (на этот раз после успеха) и требует `clean`.
4. Если новой расшифровки нет и результат `skipped`/`failed`, старая глава уже удалена и в книгу не попадёт. Это сделано намеренно: английский текст не должен оказаться в русской книге.
5. `--limit N` инвалидирует только первых N кандидатов; остальные видео не трогаются.
6. После успешного обновления запустите `clean` или `all`, чтобы создать новые главы.

Если язык не меняется, но указан `transcripts --force`, инвалидация происходит **после успешного** скачивания. Если `--force`-запрос завершился `skipped`/`failed`, старая глава остаётся. Если же язык не совпадал, инвалидация происходит до запроса, как описано выше.

`clean --language` меняет только язык аннотаций и не инвалидирует текст. `build --language` меняет только метаданные EPUB.

### Сброс данных

Полный сброс:

```bash
rm -rf data out
```

После этого `fetch`/`all` создадут каталоги и базу заново.

Частичный сброс:

```bash
rm -rf data/cache/llm     # только кэш LLM; главы останутся
rm data/state.sqlite      # только состояние; файлы расшифровок/глав останутся
rm -rf data/transcripts   # сырые и нормализованные расшифровки
rm -rf data/cleaned       # очищенные/скопированные главы и аннотации
```

Если удалить только `state.sqlite`, файлы останутся, но `ybook` не будет знать, к каким видео они относятся; потребуется новый `fetch`/`transcripts`/`clean`. Для смены канала безопаснее удалить весь `data/`.

## Ошибки и диагностика

### Конфигурация и порядок запуска

| Сообщение | Что проверить |
|---|---|
| `Config file not found: ...` | Путь в `--config`; файл должен существовать, каталог должен содержать `ybook.toml`. |
| `Invalid TOML in ...` | Синтаксис TOML: кавычки, скобки, секции. |
| `Invalid configuration ...` | Типы и диапазоны значений; см. [«Валидация»](#валидация). Неизвестные ключи не вызывают ошибку. |
| `Channel is not configured. Pass --channel or set channel in ybook.toml.` | Задайте `channel` в TOML, `--channel` или `YBOOK_CHANNEL`. |
| `No videos in the database. Run 'ybook fetch' first.` | Сначала выполните `fetch` (или `all`). |
| `This database already contains another channel ...` | Используйте чистый `data/` или удалите `data/state.sqlite`. |

Ожидаемые ошибки печатаются как `Error: ...` и завершают команду с кодом 1; неожиданные исключения показывают traceback.

### YouTube API: `403 quotaExceeded`

Дневная квота исчерпана. Что делать:

- дождаться сброса (обычно полночь по тихоокеанскому времени);
- использовать другой проект/ключ;
- запросить увеличение квоты в Google Cloud;
- помнить, что `search.list` для `/c/...` стоит 100 единиц и используется только как fallback.

`quotaExceeded` не повторяется автоматически. `fetch` каждый раз расходует квоту заново; кэша ответов API нет.

### YouTube API: `403 keyInvalid`, `401`, ключ не виден

Проверьте:

- ключ создан в том же проекте, где включён YouTube Data API v3;
- ограничения ключа (API/IP/referrer) не блокируют вызов;
- `YOUTUBE_API_KEY` (или переменная из `youtube.api_key_env`) видна процессу;
- `.env` лежит в каталоге конфига или в текущем каталоге; уже заданная переменная процесса имеет приоритет;
- при `--config /path/to/ybook.toml` CLI загружает `/path/to/.env` и `./.env`.

Сообщение `YouTube API key is invalid or restricted` означает именно проблему ключа/ограничений, а не квоту.

### Канал не найден или URL не поддерживается

- Для `/c/...` используется `forHandle` → `forUsername` → `search.list`; если канал приватный или удалён, поиск может не найти его.
- Для `@handle` и `UC...` проверьте написание; `UC...` должен соответствовать шаблону `UC[A-Za-z0-9_-]{2,}`.
- Ссылки на видео, плейлисты, `youtu.be`, `shorts/<video>` не поддерживаются — нужна ссылка на канал, `@handle` или `UC...`.
- Ошибка «This database already contains another channel» означает, что `data/` уже привязан к другому каналу. Используйте чистый `data/` или удалите `data/state.sqlite`.

### Bot check и блокировки YouTube

Симптомы: `Sign in to confirm you're not a bot`, `HTTP Error 429`, `IpBlocked`, `RequestBlocked`, `PoTokenRequired`, пустой список субтитров.

Что делать:

1. обновите `yt-dlp`: `pip install -U yt-dlp` или `uv sync --upgrade`;
2. укажите браузер для cookies: `cookies_from_browser = "firefox"` (или `chrome`, `chromium`, `edge`, `brave`);
3. уменьшите `transcripts.workers` и увеличьте `sleep_requests`;
4. повторите позже;
5. проверьте, что субтитры вообще есть у видео.

Cookies из браузера применяются только к `yt-dlp`. Если `youtube-transcript-api` получает `IpBlocked`/`PoTokenRequired`, автоматического обхода в проекте нет — остаётся `provider = "yt-dlp"` с cookies или ожидание. `yt-dlp` и `youtube-transcript-api` неофициальны; YouTube может менять защиту.

### Нет расшифровок

Если у видео нет субтитров на выбранном языке, оно получает `skipped` — это нормальный результат, а не сбой. `ybook` не скачивает аудио и не запускает ASR. Проверить доступные языки можно внешними инструментами, например:

```bash
python -m yt_dlp --list-subs "https://www.youtube.com/watch?v=VIDEO_ID"
```

Это диагностическая команда `yt-dlp`, а не функция `ybook`. Приоритет языков задаётся `transcripts.languages`; `--language` заменяет список одним языком.

### Режим без LLM: глава `failed`

Симптом: `clean --no-llm` показывает `Failed`, глава не попала в EPUB. Причины: `data/transcripts/<video_id>.txt` отсутствует, пуст или не читается. Проверьте `chapters.error` и `ybook status`:

```bash
sqlite3 data/state.sqlite "SELECT video_id, status, error FROM chapters WHERE status = 'failed';"
```

`clean --no-llm` не создаёт расшифровки — сначала выполните `ybook transcripts`. Старый `data/cleaned/<video_id>.txt` мог остаться на диске как страховочная копия, но база на него не ссылается; после исправления запустите `clean --no-llm` снова (при необходимости с `--force`).

### LLM: `401`/`403`

Эта ошибка возможна только при включённом LLM (`llm.enabled = true` или явно указан `--llm`); в режиме без LLM ключ LLM не требуется. Неверный ключ, заголовок `Authorization` или ограничения провайдера. Проверьте:

- `llm.api_key_env` и значение этой переменной;
- не остался ли в окружении старый ключ другого провайдера;
- `YBOOK_LLM_API_KEY` как резерв (только он, не `OPENAI_API_KEY`, если имя другое);
- баланс/права ключа у провайдера.

### LLM: `404`

Обычно неверный `base_url`. Код сам добавляет `/chat/completions`, поэтому:

- OpenAI: `https://api.openai.com/v1`;
- OpenRouter: `https://openrouter.ai/api/v1`;
- DeepSeek: `https://api.deepseek.com/v1`;
- Ollama: `http://localhost:11434/v1`.

Не указывайте `/chat/completions` в `base_url`. Завершающий `/` допустим — он убирается.

### LLM: `400` и `max_tokens`

Если провайдер пишет, что `max_tokens` не поддерживается:

```toml
max_tokens_param = "max_completion_tokens"
```

Значение `max_tokens` при этом не меняется. Если модель не принимает `temperature`, клиент всё равно её отправляет — это ограничение текущей реализации.

### LLM возвращает пустоту или обрезанный текст

Проверьте:

- `max_tokens` — увеличьте, если ответ обрывается;
- `max_words_per_chunk` — уменьшите, если чанк слишком большой;
- лимиты и контекст модели у провайдера;
- `temperature` — слишком высокая может давать нестабильный результат.

Глава с предупреждениями получает `needs_review` и **всё равно попадает** в книгу. Глава, где LLM не вернул пригодный текст, получает `failed` и в книгу не попадает. Если пустой ответ после повтора — смотрите `chapters.error` в базе.

### Аннотации не создаются

Симптомы: глава есть, аннотации нет, статус `needs_review`, предупреждение `annotation failed`.

Что делать:

- если используется `--no-llm` или `llm.enabled = false`, аннотации не генерируются намеренно; существующие сохраняются, пока не выполнен `clean --force --no-llm`;
- в LLM-режиме запустите `ybook clean` ещё раз — выполнится annotation-only backfill без повторной очистки;
- проверьте ключ/модель/лимиты LLM;
- если `book.annotations = false` или использован `--no-annotations`, новые аннотации намеренно не генерируются; без `--force` существующие аннотации остаются;
- `clean --force` при выключенных аннотациях (`--no-annotations` или `book.annotations = false`) удаляет аннотации после успешной очистки;
- `clean --language ru` меняет язык только новых/перегенерированных аннотаций, не текст главы.

### `No cleaned chapters are available`

Точное сообщение:

```text
No cleaned chapters are available. Run 'ybook transcripts' and 'ybook clean' first
(or check include_shorts/include_live filters).
```

Проверьте:

- `ybook status`: есть ли `transcripts ok` и `chapters cleaned/needs_review`;
- существуют ли файлы в `data/cleaned/` (пути в базе абсолютные);
- не отфильтрованы ли главы через `include_shorts`/`include_live`;
- не относится ли глава к другому каналу в смешанной базе;
- не осталась ли глава в `failed` после неудачной очистки.

Если расшифровок нет вообще, сначала выполните `fetch`, затем `transcripts`, затем `clean`.

### EPUB не открывается

- Проверьте файл внешним `epubcheck`:

```bash
epubcheck out/book.epub
```

- Убедитесь, что файл не нулевого размера и сборка не прервалась.
- Отсутствие обложки — нормально; это не ошибка EPUB.
- Попробуйте пересобрать: `ybook build`.
- Если `build` пишет `No chapters to build`, проверьте очищенные файлы и фильтры.

### Где база?

`ybook status` печатает путь. По умолчанию:

```text
<каталог конфига>/data/state.sqlite
```

Если конфига нет — `<текущий каталог>/data/state.sqlite`. Путь можно изменить через `paths.data_dir`. Для ручной проверки:

```bash
sqlite3 data/state.sqlite ".tables"
sqlite3 data/state.sqlite "SELECT video_id, status, error FROM chapters LIMIT 10;"
```

### Промпты

Промпты лежат в `src/ybook/prompts.py`. Чтобы изменить поведение очистки или аннотаций:

1. отредактируйте `CLEANING_SYSTEM_PROMPT`, `ANNOTATION_SYSTEM_PROMPT` или шаблоны сообщений;
2. **увеличьте `PROMPT_VERSION`** — иначе кэш LLM продолжит отдавать старые ответы;
3. запустите тесты `pytest -q` и проверьте очистку с `--limit 1` (или 2–3);
4. при необходимости очистите кэш `rm -rf data/cache/llm`.

Промпты намеренно на английском; язык результата задаётся текстом (очистка) или параметром `language` (аннотация). Не добавляйте в промпт инструкции, которые противоречат quality guard: например, «сократи текст» вызовет предупреждение о соотношении длины.

### Добавление LLM-провайдера

Если провайдер совместим с OpenAI Chat Completions:

1. укажите `llm.base_url`, `llm.model`, `llm.api_key_env` и при необходимости `extra_headers`;
2. задайте ключ в `.env` или окружении;
3. проверьте `max_tokens_param` (`max_tokens` или `max_completion_tokens`);
4. выполните `ybook clean --limit 1` и посмотрите на ошибки; стоимость при необходимости проверьте в `chapters.cost_usd`.

Для несовместимого протокола нужно менять код:

- `src/ybook/llm.py` — `chat`, `_send`, `_parse_response` (payload, заголовки, разбор ответа);
- `src/ybook/config.py` — новые поля, если они нужны;
- тесты в `tests/test_llm.py` — payload, usage, ошибки, кэш.

SDK провайдера не используется: проект намеренно говорит на plain HTTP через `httpx`.

## Безопасность

- **Ключи только из окружения.** В `ybook.toml` хранятся имена переменных (`api_key_env`), а не сами ключи. Не вписывайте ключи в TOML.
- **`.env` не коммитится.** `.gitignore` игнорирует `.env`, `.env.*` (кроме `.env.example`), `data/`, `out/`, `*.epub` и файлы cookies (`cookies*.txt`, `*.cookies.txt`, `cookies/`).
- **Cookies не коммитятся.** `cookies_from_browser` передаёт `yt-dlp` имя браузера; `ybook` не сохраняет cookies в свой репозиторий. Не добавляйте cookie-файлы в git.
- **Ключи не попадают в SQLite, EPUB, снимки API и сообщения об ошибках.** Снимки `data/api/*.json` санитизированы; ключ вырезается из текстов ошибок YouTube и LLM.
- **Ограничивайте ключ YouTube** в Google Cloud: только YouTube Data API v3 и, по возможности, IP.
- **LLM получает содержимое расшифровок** (и названия канала/плейлиста/видео). Для конфиденциальных материалов используйте локальную модель (Ollama), режим без LLM или провайдера с подходящей политикой.
- **Режим без LLM держит текст локально.** При `--no-llm` или `llm.enabled = false` расшифровки не отправляются на endpoint: `clean` только копирует локальные файлы. Взамен теряются редактирование, quality guard и аннотации — качество текста остаётся на уровне исходной расшифровки.
- **Логи.** `--verbose` включает DEBUG; не публикуйте логи и снимки API без проверки. Ключи редактируются, но заголовки, ID и тексты ошибок могут быть чувствительными.
- **Данные и EPUB** могут содержать чужой контент; каталоги `data/`, `out/` и `*.epub` исключены из git, чтобы случайно не опубликовать книгу.

## Ограничения

- **Неофициальные источники субтитров.** `youtube-transcript-api` и `yt-dlp` не являются продуктами YouTube/Google; их работа не гарантирована. YouTube может изменить защиту, и загрузка сломается.
- **Нет ASR.** Видео без готовых субтитров пропускаются; аудио не скачивается.
- **Нет перевода.** Очистка сохраняет язык оригинала; машинные переводы авто-субтитров отклоняются. Книга на новом языке возможна только при наличии субтитров на нём.
- **Только EPUB, без обложки.** Других форматов и изображений нет.
- **Только публичный контент.** Приватные, удалённые, DRM-защищённые и платные материалы не поддерживаются.
- **Качество LLM не гарантировано.** Очистка может потерять нюансы, а аннотация — ошибиться. Quality guard ловит только часть проблем.
- **Режим без LLM не редактирует текст.** Пунктуация, регистр и абзацы не восстанавливаются, quality guard и аннотации не работают; качество зависит от исходных субтитров/ASR. Зато текст не отправляется LLM, а стоимость равна нулю.
- **Квота YouTube.** Большие каналы и частые `fetch` расходуют дневную квоту; `search.list` для `/c/...` дорогой.
- **Стоимость LLM.** Зависит от провайдера, модели и длины текста; `ybook` считает стоимость только если заданы цены и провайдер вернул usage.
- **Один канал на `data/`.** Смена канала требует чистого каталога или удаления базы.
- **Нет миграций SQLite.** Несовместимое изменение схемы требует пересоздания базы.

## Что дальше

- Начните с `ybook all --limit 3`, чтобы проверить ключи, субтитры и качество LLM на небольшой выборке. Если LLM не нужен, используйте `ybook all --limit 3 --no-llm`.
- Посмотрите `ybook status` и предупреждения `needs_review`; при необходимости поправьте промпты и пересоберите книгу.
- Для регулярного обновления запускайте `ybook all` — повторные запуски идемпотентны, а `build` всегда пересобирает EPUB из текущего состояния.
- Перед публикацией или передачей книги проверьте её через `epubcheck` и убедитесь, что у вас есть права на исходный контент.
